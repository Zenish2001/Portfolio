ChainProof

Complete

A crypto trading bot where four indicators vote (RSI, MACD, an SMA 20/50 crossover and Bollinger Bands) and two agreeing signals trigger a trade, with stop-loss and take-profit risk controls.

On top of it sits an on-chain verification layer on Ethereum Sepolia: 30 trading decisions hashed with keccak256, signed with ECDSA and committed to a Solidity registry. A standalone verifier checks every hash and signature against the chain from a clean clone, and changing a single price or signal breaks the match.

The agent is registered under ERC-8004, the draft standard for trustless agent identity, as agentId 9896. The official deployments include no Validation Registry, so I wrote and deployed one, with a validator that can only publish verdicts for decisions that were actually committed. Its 19 Foundry tests run against the live Sepolia registries and surfaced a real bug: the reference implementation calls a function the canonical registry doesn't have, so it reverts in production. Every push re-runs 33 tests and re-verifies the chain in CI.

You don't have to trust the screenshots. This checks all 30 commitments against Sepolia in about ten seconds, with no keys or accounts:

cd ChainProof/verification-layer
pip install -r requirements.txt

What these mean

Concepts used

🔑

Private & Public Key

A key pair. The private key is a secret number only you hold, used to sign messages and prove ownership. The public key is derived from it and safe to share; others use it to verify your signature without ever seeing the private key itself.

#

Hash

A function that turns any input into a fixed-length string of characters. The same input always produces the same hash, and changing even one character changes the entire result.

⛂

Block & Blockchain

A block is a bundle of data sealed together with a hash. A blockchain is a chain of these blocks, each one referencing the hash of the one before it, so editing an old block would break every block after it.

🎯

Nonce (SHA-256)

A one-time number combined with data and run through a hashing function. Change the nonce and the whole output changes; that's how a result can be tied to one specific attempt.

🌳

Merkle Proof

A way to prove one piece of data belongs to a larger set, without revealing the whole set, by checking it against a chain of paired hashes up to a single "root" value.

🤝

Consensus

How multiple independent parties agree a piece of information is valid. Instead of trusting one source, a majority has to confirm it first.

⚙️

Smart Contract Call

Running a small piece of code stored on a blockchain and getting back whatever it returns, the same way an app might call a function, but the code and result are both publicly checkable.

✏️

Digital Signature

Proof that a message really came from a specific person, created with a private key only they hold, and checkable by anyone using the matching public key.
